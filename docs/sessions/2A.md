# Sesión 2A Carga segura de originales

## Entregable

Documentos y versiones originales persistidos mediante migración 0004, con propietario,
visibilidad inicial RESTRICTED, filename normalizado, MIME verificado, tamaño, SHA-256 y object
key interna única. ADMIN/KM pueden subir; owner y ADMIN consultan metadata de esa versión.
Se rechazan IDs ajenos con la misma respuesta que un recurso inexistente.

La validación estructural acepta PDF/DOCX/TXT/MD del corpus y limita tanto archivo como sobre
multipart. No confía en el MIME enviado. Reservas persistidas antes de PUT permiten recuperar
una interrupción entre MinIO y la confirmación final. El mantenimiento explícito distingue
objeto ausente, contenido corrupto y fallo transitorio; limpia escrituras fallidas pendientes.
Contrato y límites en [ADR 0007](../adr/0007-upload-originals.md).

## Evidencia

Verificado el 16 de octubre de 2026:

- Migración 0004 aplicada; `alembic check` sin diferencias.
- Ruff, mypy estricto (61 archivos), lint/tipos/build web y formato: PASS.
- 23 pruebas de validación: ocho originales reales, límites exactos, firmas falsas, UTF-8,
  PDF cifrado, path traversal, macros, ZIP duplicado, expansión excesiva y entidades XML.
- Pruebas API contra PostgreSQL/MinIO reales verifican bytes/hash en los ocho formatos del
  corpus, roles, ID ajeno, límites de multipart también sin Content-Length y metadata privada.
- Inyección de fallo después de PUT real: cleanup y estado UPLOAD_FAILED comprobados.
  Interrupción de commit: reserva UPLOADING recuperada mediante tamaño/hash.
  Ausencia, corrupción, caída temporal y cleanup fallido se distinguen; una versión publicada
  no puede borrarse desde el mantenimiento de uploads.
- HTTP real con Uvicorn: login KM, subida de `politica_viajes.pdf`, consulta autorizada y logout:
  PASS. El original sintético permanece disponible en la base demo local.
- Trece pruebas web de 1C continúan en PASS; no se presenta este trabajo como evaluación RAG.

Las pruebas API usan esquemas transaccionales aislados y eliminan únicamente sus propias keys
S3 registradas. El corpus permanece intacto. No se han subido documentos privados del usuario.

## Límites

Las cargas exitosas permanecen UPLOADED; aún no se extraen ni se indexan. Esta sesión no afirma
haber completado antivirus ni una garantía transaccional distribuida. Los estados y la
reconciliación documentan explícitamente la frontera S3/PostgreSQL. Visibilidad configurable,
grants, biblioteca y nuevas versiones del mismo documento llegan en 2B; jobs, en 2C.
