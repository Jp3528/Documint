# Sesión 2R Revisión de biblioteca y cola

## Resultado

Se verificaron aislamiento por documento, conservación de originales y jobs lógicos,
concurrencia y fallos entre base de datos, almacenamiento y publicación. No se encontró un
bypass en los casos ejecutados. Los originales de la demo continúan pendientes de pipeline;
ningún job real se ha marcado READY.

## Evidencia

Verificado el 16 de octubre de 2026:

- **127 pruebas Python PASS**, con PostgreSQL, Redis y MinIO reales, sin omisiones.
- **20 pruebas web PASS**; Ruff/formato, mypy (76 archivos), lint/tipos/build web y formato: PASS.
- Dos conexiones PostgreSQL independientes crean versiones concurrentemente: números 2 y 3,
  tres keys distintas, original v1 intacto y exactamente un job lógico por versión.
- Dos dispatchers compiten por la misma fila confirmada: SKIP LOCKED permite una publicación.
  El publisher es un spy explícito para medir el lock, sin presentarlo como entrega Redis.
- Publicación seguida de fallo de commit: el mensaje ya emitido procesa el job PENDING; una
  segunda entrega mantiene WAITING_PIPELINE con attempts=0. La entrega Redis real y su duplicado
  permanecen comprobados por la prueba de 2C en una cola UUID aislada.
- Fallo de la reserva SQL antes de PUT: respuesta 503, cero objetos escritos y cero documentos/jobs.
  Multipart inválido/truncado: 400/422 sin originales ni registros persistidos.
- Se mantienen los negativos de 2A/2B: MIME falso, tamaño, ZIP/XML, ID ajeno antes de S3,
  READ distinto de MANAGE, revocación con el mismo token, archivo y departamento inactivo.
- Retry no duplica UUID ni aumenta el límite de procesamiento; broker y ejecución conservan
  contadores separados. READY simulado solo aparece en el esquema aislado de una fixture.

Las pruebas concurrentes crean un esquema PostgreSQL exclusivo y confirmado para compartirlo
entre conexiones. Eliminan solo sus keys S3 y ese esquema `test_concurrent_<uuid>`; no usan
usuarios, permisos o documentos demo existentes. Los tests de una conexión siguen usando
rollback transaccional de DDL y datos.
