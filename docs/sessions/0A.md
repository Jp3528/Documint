# Sesión 0A Inicialización del repositorio

## Entregable

Monorepo con FastAPI, worker Celery y web React/TypeScript/Vite. Incluye `/health`, una página
de estado que consulta la API y una tarea de smoke sin lógica documental. Ruff, mypy, pytest,
ESLint, TypeScript, Vitest, Prettier y GitHub Actions quedan configurados desde el inicio.

## Criterios de cierre

- API responde a `/health` y documenta su contrato en OpenAPI.
- Frontend compila y comprueba la conexión sin inventar un estado exitoso.
- Worker ejecuta su tarea a través de un transporte de prueba real, sin modo eager.
- Los checks locales de Python y frontend pasan; el workflow replica esos comandos.
- README contiene comandos reproducibles y distingue liveness de readiness.

Comando completo: `uv run python -m scripts.check`.
La captura [0A-api-connected.png](../screenshots/0A-api-connected.png) conserva evidencia del
flujo real. En el primer workflow remoto pasó el job web. El job Python detectó que el action
setup-uv no publica la etiqueta general v10; se corrigió fijando el SHA publicado de v10.3.0.
La ejecución remota de la corrección queda pendiente de confirmar.

Se utiliza npm 11.6.2 para evitar un fallo de resolución de peers de npm 10. Vite tiene
configuración PostCSS explícita para no heredar accidentalmente archivos de un directorio padre.
El runner CI se fija a Ubuntu 24.04 para evitar cambios automáticos de imagen del sistema operativo.

## Límites

No se ha implementado autenticación, uploads, retrieval ni generación. La prueba de worker
usa transporte de memoria y no demuestra conectividad con Redis. Los servicios locales y
readiness corresponden a 0B.
