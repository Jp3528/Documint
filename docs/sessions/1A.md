# Sesión 1A Autenticación y sesiones revocables

## Entregable

Usuarios con email normalizado/único y contraseña Argon2id. Login, refresh, logout y perfil
funcionan mediante servicios separados de routers. JWT HS256 de cinco minutos con claims
obligatorios y validación de issuer/audience/tipo. Refresh aleatorio guardado solo como hash,
cookie HttpOnly y Strict, rotación con locks de filas y revocación persistida por familia.

La migración `0002` crea usuarios, familias y hashes refresh. No se usa create_all en runtime.
Los comandos explícitos inicializan la clave privada local, crean cuentas propias o las diez
identidades de demo; el seed es idempotente, preserva credenciales y rechaza production.

## Evidencia

Verificado el 15 de octubre de 2026:

- Ruff y mypy estricto: PASS, 43 archivos de tipos.
- `uv run alembic upgrade head` y `uv run alembic check`: PASS; sin drift del modelo.
- Suite completa con `DOCUMIND_TEST_INFRA=1 uv run pytest`: **44 PASS**, sin omisiones.
- Once pruebas de seguridad: Argon2 salado, tiempos/claims, firma incorrecta/ausente,
  configuración ausente, CSRF y validación que no repite contraseñas.
- Diez pruebas de API/sesiones con PostgreSQL real: login/perfil, rotación/replay, logout,
  inactividad, expiración, múltiples sesiones, seed y concurrencia.
- Dos conexiones PostgreSQL compiten por el mismo refresh: un solo ganador; el intento repetido
  revoca la familia y bloquea incluso el access recién emitido.
- La clave `.env` generada permanece ignorada por Git; repetir init_env conserva el archivo.

Las fixtures API hacen rollback de sus datos. La prueba concurrente usa una identidad con UUID
exclusivo y limpia solo sus filas. La prueba de seeds usa personas con IDs/emails únicos, sin
depender de que la base local ya tenga o no las cuentas demo.
