# Esfuerzo y condiciones de avance

El plan 1.1 conserva nueve fases y 36 sesiones. Una semana identifica una fase de referencia;
no obliga a comprimir su trabajo en siete días. Cada sesión avanza al pasar sus criterios de
cierre y registrar pruebas y limitaciones. Los rangos incluyen implementación, pruebas y docs.

| Fase         | A    | B    | C    | R    | Total horas |
| ------------ | ---- | ---- | ---- | ---- | ----------- |
| 0 Fundación  | 4–6  | 4–6  | 6–8  | 2–4  | 16–24       |
| 1 Identidad  | 6–10 | 6–10 | 6–8  | 3–5  | 21–33       |
| 2 Biblioteca | 6–10 | 6–10 | 6–10 | 3–5  | 21–35       |
| 3 Pipeline   | 8–12 | 6–10 | 6–10 | 4–6  | 24–38       |
| 4 Retrieval  | 6–10 | 4–6  | 6–8  | 6–10 | 22–34       |
| 5 RAG y chat | 4–6  | 6–10 | 8–12 | 6–10 | 24–38       |
| 6 Operación  | 6–10 | 4–6  | 6–10 | 4–6  | 20–32       |
| 7 Calidad    | 6–10 | 6–10 | 6–10 | 4–6  | 22–36       |
| 8 Despliegue | 6–10 | 6–10 | 4–6  | 4–6  | 20–32       |
| Total        |      |      |      |      | **190–302** |

P-MASTER añade 1–2 horas de preparación. Las estimaciones suponen una persona con bases de
Python, React, APIs y Docker. Aprendizaje adicional, esperas externas y contingencias se suman
por separado; estos valores no son horas efectivamente trabajadas ni una promesa de calendario.
Completar nueve fases en nueve semanas supondría unas 21–34 horas netas por semana.
