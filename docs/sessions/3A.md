# Sesión 3A Parsers y snapshots de extracción

## Entregable

Registro tipado para PDF/DOCX/TXT/Markdown, con límites y bloques normalizados. Locators de página,
párrafo/tabla/heading o líneas permiten volver al original sin inventar paginación. La migración
0007 persiste snapshots por versión/revisión de parser con hashes y contadores verificables.
Los errores de una etapa explícita se reflejan en job y versión como FAILED con código seguro.

El comando `scripts.extract_job <job_id>` ejecuta solo extracción y deja EXTRACTED pendiente de
chunking/índice. El task de Celery sigue esperando al runner completo de 3C. No se presenta
esta etapa parcial como un documento disponible para búsqueda. Ver [ADR 0009](../adr/0009-parsers.md).

- Migración 0007 aplicada; `alembic check` sin diferencias.

  PDF combinado con páginas 1/2, heading/orden/tablas y celdas Word combinadas, líneas TXT,
  encabezados y código Markdown, límites y documento PDF sin texto.
- Cinco casos nuevos con PostgreSQL/MinIO: snapshots de los ocho originales, reuso sin duplicar
  ni consumir otro intento, contadores/locators, FAILED sin bloques parciales ante PDF vacío,
  integridad de S3 o límite, y rechazo de snapshot cacheado alterado.
- Una excepción del parser se convierte en PARSER_FAILED sin repetir su mensaje privado.
  Instrucciones maliciosas de un Markdown permanecen como texto de datos.
- Operación local: las tres versiones sintéticas de la demo pasaron por el comando de extracción;
  API confirma stage=EXTRACTED, status=WAITING_PIPELINE y attempts=1. Los originales se conservan
  y las versiones quedan CHUNKING, sin marcar READY.
