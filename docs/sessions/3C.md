# 3C. Embeddings y pipeline completo

Verificado el 22 de octubre de 2026. Implementación y comprobaciones locales: PASS.

El worker conecta originales privados, extracción, chunks, embeddings pgvector y activación.
READY requiere todos los vectores del perfil correcto y se confirma junto con SUCCEEDED y el
puntero activo. Los IDs y chunks publicados permanecen inmutables. El modo de demostración
FAKE está identificado en API/UI y prohibido en producción. El adaptador OpenAI está disponible
con configuración explícita; no se ha ejecutado una evaluación pagada ni se afirma calidad real.

## Evidencia

- Suite completa con `DOCUMIND_TEST_INFRA=1`: **183 pruebas Python PASS**, sin omisiones.
- Dos casos adicionales de reindexación fallida y perfil inmutable: PASS; suite focalizada
  del pipeline con sus seis casos completa, PASS. Total actual: 185 pruebas Python.
- **22 pruebas web PASS**; lint, tipos, build, Ruff, formato y mypy estricto: PASS.
- Migración 0009 y `alembic check` sin diferencias. Conserva los datos anteriores.

- Interrupción tras 32 vectores: el reintento conserva los anteriores y solicita los restantes,
  sin duplicar revisión, chunks, recibos ni vectores.
- Interrupción del commit final: ni READY ni el puntero activo sobreviven al rollback.
- Duplicado durante ejecución retorna RUNNING. Sustituir el token impide al worker anterior
  escribir vectores o activar; el dispatcher recupera el lease vencido.
- Stubs HTTP verifican el contrato real del adaptador: reordenación, índices faltantes o
  duplicados, modelo/dimensiones incorrectos, NaN/infinito, límites y errores sin mensajes
  privados. Se valida consumo, sin inventar el costo. No son llamadas reales a OpenAI.

## Operación

Usar worker y dispatcher según README. Para un trabajo concreto:
`uv run python -m scripts.process_job <UUID>`. Los WAITING_PIPELINE previos se recuperan por
el dispatcher. Los trabajos fallidos admiten el mismo endpoint de retry, hasta su límite;
un trabajo completado requiere otra clave de pipeline si se desea otra configuración.

Detalles y límites de costos, configuración del proveedor, leases y parsing en
[ADR 0011](../adr/0011-embedding-pipeline.md). La evaluación real de embeddings permanece en 4R.
